# Realtime protocol subset

The gateway advertises protocol `openai-realtime-subset`, version `1.0.0`. Clients connect to `/v1/realtime` through the authenticated gateway. Unknown event types, duplicate object keys, unknown security-sensitive fields, malformed UTF-8, excessive JSON depth, and configured frame/audio limits fail closed.

## Client events

The accepted subset is `session.update`, `input_audio_buffer.append`, `input_audio_buffer.commit`, `conversation.item.create`, `response.create`, `response.cancel`, and `live.tool.approval.resolve`. Approval resolution carries only an invocation ID, `approved` or `denied`, a bounded reason, and an idempotency key; identity and tool inputs are server-authoritative.

## Server events

The gateway emits `session.created`, `session.updated`, `error`, speech start/stop, input transcription delta/completed, `response.created`, output audio delta/done, output transcript delta/done, function-call completion, and `response.done`.

The durable extensions are:

- `live.handoff.created`, `.progress`, `.needs_input`, `.completed`, `.failed`, and `.cancelled`, each correlated by stable event sequence and handoff ID.
- `live.session.degraded` and `live.session.resumed` for bounded recoverable service state.
- `live.tool.approval.required`, which exposes a bounded action summary and risk class but no executable inputs.
- `live.tool.approval.resolve`, the only client-to-server extension.

Reconnect restores only committed durable state and advances exact delivery cursors. Response incarnation and epoch fence every provider event. A cancellation advances the fence before later output can be presented; stale output is discarded and counted.

## Reserved tools

The model-facing reserved names are `start_background_task`, `steer_background_task`, and `cancel_background_task`. Start accepts `objective` and optional `presentation_hint`. Steer accepts `handoff_id` and `objective`. Cancel accepts `handoff_id` and optional `reason`. The parser admits one exact JSON object, rejects unknown or server-derived fields, and bounds every string. Ordinary tools cannot enter the handoff path.

## Audio

Input and output are base64-transported `pcm_s16le`: mono, 24,000 Hz, two bytes per sample, 20 ms frames, 960 bytes per full frame. A final even-byte partial frame may be flushed on commit. Empty commits, split samples, wrong formats, and oversized payloads are rejected. Production audio is never watermarked; the release canary uses bounded text sentinels only inside its two dedicated synthetic sessions.

Capability data is generated by `internal/protocol.Capabilities`; clients should negotiate against it rather than assuming the full upstream Realtime API.
